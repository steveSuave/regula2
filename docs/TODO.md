## Phase 143 — M-P2b: the DD rule core and the resumable fixpoint

The second third of M-P2 (PLAN §M-P2): the rules and the engine that runs them, built on Phase 142's fact database and Phase 141's filter. Hypotheses are read off the construction, the ~20-rule DD core comes from the open DDAR/Newclid sources (rules, not code), every candidate deduction is screened through `DiagramFilter` before insertion, and the whole thing runs to quiescence in Phase 140's resumable shape with a rule-application budget. This is also the phase where the `MessageChannel` yield stops being a measurement and becomes an API, because an engine that actually chunks is its first consumer.

- [x] **Hypothesis extraction** (`lib/domain/prover/hypotheses.dart`): read the predicate vocabulary off a construction's parent ties, never its positions — incidence-shaped facts (`coll`/`cyclic`/radius-`cong`) through `incidence.dart`'s zero-epsilon relation, per-kind statements for every kind with a pointwise theorem (midpoints, reflections, projections, triangle centers, the bisector lines, Thales on a diameter circle, the compass transfer, the harmonic eqratio). Point-tuple vocabulary means a line's facts need witness pairs — a carrier with one known point contributes nothing, honestly. Euclidean only, refused rather than approximated. The test's spine: every emitted hypothesis must survive the filter on the rig that emitted it
- [x] **The rule core** (`rule.dart`): 23 DD rules from the DDAR/Newclid sources as data — premises and conclusion over pattern variables in the sources' own notation, a conclusion only naming variables its premises bound. `simtri → eqangle` deliberately absent: orientation-free `simtri` admits the reflected pair that negates every mod-π angle. The sources' `ncoll` side conditions are carried by the filter screen, and the screen test pins that (a structurally-true collinear eqangle fires `isosceles_converse` and is refused)
- [x] **The engine** (`rule_engine.dart`): semi-naive chaining — each fact pivots once, remaining premises joined over the facts stored when its turn began, binding against every spelling of a stored fact (`orbitArguments`, the full orbit with within-segment swaps the canonicalizer sorts away). Every candidate conclusion screened through `DiagramFilter` before insertion; structural degeneracy refused at binding time without spending budget. The per-kind index lives in the engine — the consumer M-P2a named. `step(budget)` counted in rule applications, `step(1)` chunking bit-identical to a straight run (pinned). **`Isolate.run` wrapping is deferred with the consumer named**: facts key by point identity, so crossing an isolate needs an id-based transfer, and that design belongs to the first UI consumer (M-P2c/M-P4) rather than on spec
- [x] **The `MessageChannel` yield's real home** (`event_loop_yield.dart`): `dart:js_interop` arm behind a conditional import beside the native zero-timer arm — never a runtime capability check. `ProverEngine.runChunked` drives `step` through it. The browser gate holds the seam: `test/web/prover_yield_web_test.dart` pins that the *shipped* yield shows no setTimeout clamp (0.033 ms against the timer's 4.582 — the wrong-arm failure is silent everywhere else) and that a chunked browser fixpoint derives the straight run's database
- [x] Tests mirroring under `test/domain/prover/`: per-kind extraction with the filter pin; each of the 23 rules fired on a rig where premises *and* conclusion are structural theorems; the side-condition screen; quiescence, budget adherence, chunked determinism; a depth-three chain (`midp` → `coll` + midline → intercept eqratio) and the Varignon parallelogram via `para_transitive`; every premise strictly older than its conclusion (the M-P2c walk's contract); `orbitArguments` sizes, sameness, and least-element agreement with the canonicalizer
- [x] Gates: suite **2893** green (2842 + 51), analyze clean, browser gate green (now carrying `prover_yield_web_test`'s two), wasm build compiles. Mutation-checked: dropping the orbit's transpose family fails exactly the two orbit pins plus the three matcher tests that need transpose spellings (`eqangle`/`eqratio` transitivity, the similarity criteria); removing the filter screen fails exactly the side-condition test. The layer rule fired on the web arm and was extended deliberately: `dart:async` allowlisted, `dart:js_interop` allowed only in `*_web.dart` conditional-import arms

## Phase 142 — M-P2a: canonical forms and the fact database

M-P2 (PLAN §M-P2) split into three, because keying, rules and proof surfacing are three sessions in one box and the first is what the other two are built on: a rule engine written against identity-compared predicates would have to be rewritten. **142 is the keying and the store**; M-P2b is the ~20-rule DD core and the resumable fixpoint; M-P2c is the proof DAG surfaced as a readable derivation. PLAN calls eqangle/eqratio canonicalization "the fiddly part" and it is the whole of this phase's difficulty.

- [x] **`Fact` — a predicate reduced to its orbit under its own symmetries** (`lib/domain/prover/fact.dart`): same (kind, points) shape as `Predicate`, same arity contract, but with value equality, so a `Set<Fact>` *is* the database. The canonical form is the lexicographically least argument order in the symmetry group of the kind, ordered by point `id`
- [x] **The symmetry group per kind, named rather than assumed**: `coll`/`cyclic` fully symmetric; `para`/`perp`/`cong` sort within each pair then between the pairs; `midp` fixes the midpoint and sorts the ends; `simtri`/`contri` admit any permutation applied to *both* triples, plus the triangle swap (12 forms) — orientation-free, so nothing else is needed; `eqangle`/`eqratio` sort within each of the four segments and then take the least of the **eight** arrangements of the 2×2 matrix `[[s1,s2],[s3,s4]]`, which is D4 generated by the row swap (the two sides commute), the column swap (negate/invert both) and the **transpose** (`∠(l1,l2)=∠(l3,l4) ⟺ ∠(l1,l3)=∠(l2,l4)`, and `s1/s2=s3/s4 ⟺ s1/s3=s2/s4`) — the one that is easy to miss and doubles the collapse
- [x] **The symmetry table is pinned against the evaluators, not against itself.** Every form the canonicalizer collapses must be *numerically* the same statement: the test asserts both that the forms key alike and that `holdsNow` agrees across them on random configurations. A canonical form that merged two different statements would silently make the prover unsound, and only the evaluator can catch it
- [x] **`FactDatabase` with provenance from day one** (`fact_database.dart`): insert-or-ignore keyed on the canonical fact, insertion order preserved, and every entry carries a `Derivation` — a hypothesis, or a rule name with its premises. **First insert wins**, which is not a tie-break but the acyclicity argument: a fact's derivation is recorded before anything derived *from* it exists, so the proof DAG M-P2c reads can never contain a cycle. `add` throws on a premise the database does not already hold, making that closure structural rather than hoped-for
- [x] **Deliberately deferred, with the consumer named**: no index by kind (M-P2b's rule matcher is what would justify one), no rule objects (a name is a `String` the database does not interpret), no hypothesis extraction from a construction, no filter coupling — the database stores what a rule derived; screening candidates stays `DiagramFilter`'s job
- [x] Tests mirroring under `test/domain/prover/` (43 new): per-kind orbit collapse against a table written out independently of the implementation's; the numeric pin over 24 random similarities of each true rig plus a broken rig; idempotence; eight plausible non-symmetries that must key apart *and* evaluate false; id-ordering independent of construction order; the database's keying, first-insert-wins, premise closure and iteration order
- [x] **Mutation-checked** against a committed baseline: dropping the transpose family fails exactly the two eight-point collapse tests, dropping the triangle swap exactly `simtri`/`contri`, dropping the pair swap exactly the three four-point ones plus the `Set` test, sorting `midp`'s three arguments exactly its non-symmetry test; adding a non-symmetry to the *test's* own table fails the numeric pin, which is the evidence that pin has teeth; last-insert-wins and an unchecked premise each fail exactly their own test
- [x] Gates: suite **2842** green (2799 + 43), analyze clean, browser gate green

## Phase 141 — M-P1: predicates + the numeric filter

The prover milestone's first code phase (PLAN §M-P1). The vocabulary DD forward chaining will range over, and the model filter that keeps it tractable: never attempt a deduction that is not numerically true in the diagram. The filter generalizes `point_coincidence.dart`'s perturbation probe from "same position" to "predicate survives perturbation" — V1 already built Cinderella's randomized theorem test; this is that test given the prover's vocabulary.

- [x] **The predicate vocabulary** in `lib/domain/prover/`: `coll / para / perp / cong / cyclic / eqangle / eqratio / midp / simtri / contri` — a kind with a fixed arity plus `GeoPoint` arguments, arity enforced as a programmer-error contract. Canonical forms (the eqangle/eqratio keying) are deliberately **not** here — they are M-P2's fact-database concern, and `Predicate` says so: it compares by identity
- [x] **Numeric evaluators as pure functions over chart positions** (`numeric_checks.dart`), dimensionless residuals against one shared tolerance (1e-6, deliberately the coincidence probe's magnitude), sitting between a true predicate's float noise and the smallest violation a probe leaves. Degenerate arguments answer conservatively (a zero direction has no parallel, a degenerate triangle is similar to nothing, a coincident pair determines no circle); the one deliberate exception is `coll` on coincident points (true — they impose no constraint a line could fail); an undefined point makes every predicate false. `simtri`/`contri` are **orientation-free** (side ratios / SSS); if M-P2's rules need Newclid's direct/reflected split it goes beside the ratio check, said at the site
- [x] **The filter samples configurations once, not once per predicate.** `DiagramFilter.probe` perturbs every mutable root, recomputes, snapshots every point's position, restores bit-exactly — `probeCount` times, up front. `holds(predicate)` then answers from the stored configurations, so M-P2 can screen thousands of candidate deductions against one sampling at no recompute cost. A point undefined in any configuration answers false; a predicate over a point the diagram never sampled throws
- [x] **The root machinery extracted, not duplicated**: `lib/domain/construction/mutable_roots.dart` (collect `FreePoint`/`PointOnObject` roots, perturb from a saved base — never cumulatively — restore bit-exactly, plus `recomputeCarriers`), re-pointing `point_coincidence.dart` at it with behaviour unchanged — same constants, same RNG draw order
- [x] **Euclidean-only, refused rather than approximated**: the vocabulary measures in the Euclidean chart (parallelism, congruence, angle equality), so a proper absolute is refused at `probe` — a CK prover re-founds the predicates at this boundary, the same place M-CK re-founded measurement
- [x] Tests mirroring under `test/domain/prover/` (43 new): per-predicate exact-true / perturbed-false / degenerate / scale cases with glados properties; the filter keeping structural truth (Varignon parallels *and* congruences, a glued point's collinearity, two glued radii of one circle) and killing accidental truth (a free point placed exactly on a midpoint — `holdsNow` true, `holds` false); bit-exact restore, with and without an undefined dependent in the graph; both refusals
- [x] Gates: suite **2799** green (2756 + 43), analyze clean, browser gate green, wasm build compiles

## Phase 140 — M-P0: the threading decision

The milestone gate PLAN puts before any prover code. Scoped as a **spike**, like Phase 101: the deliverable is a measurement and a pinned decision, not an engine — there is no prover to drive yet, and an abstraction with no consumer is what this project keeps deciding not to build on spec. Decision recorded in PLAN §"The prover yields with a MessageChannel, not a timer".

- [x] **The premise, checked rather than assumed.** `Isolate.run` **compiles cleanly** for both web targets and fails at *runtime* — `UnsupportedError: new RawReceivePort` (dart2js), a trap (dart2wasm). The compiler will not catch an isolate smuggled into shared code; only a browser run will, so the native path must be reached by conditional import rather than by a capability check
- [x] **A representative synthetic fixpoint** (`benchmark/threading_bench.dart`): a fact database plus rules deriving new facts in rounds to quiescence — DD forward chaining's *cost profile* (a growing set scanned against itself, hash-set membership on the inner loop, a queue that drains and refills), not its geometry
- [x] **The resumable shape is cheap and its cost is budget-independent**: 10% VM, 2% AOT, 11% dart2js, 4% dart2wasm against the straight-line loop, flat from 1 000 to 500 000 rule applications per step. So it is what the prover should be *everywhere*, not a web compromise — and the budget is counted in rule applications rather than milliseconds, the same argument as Phase 139's step budget
- [x] **The decisive measurement, and it had to be taken in a browser.** `await Future.delayed(Duration.zero)` is `setTimeout`, which the HTML spec clamps to 4 ms once five timeouts have nested: **5.07 ms/yield** measured in Chrome, against **0.048 ms** for a `MessageChannel` macrotask — 105×. On the fixpoint that is 16.8 s vs 109 ms on dart2wasm, and dart2js does not finish. Through the channel, sixty 4 ms chunks showed no measurable scheduling overhead. `test/web/yield_cost_web_test.dart`, pinned as properties (the timer shows a clamp; the channel is not clamped like one) rather than as machine-specific numbers
- [x] **The microtask is rejected for the opposite reason** — cheapest of the three (0.036 ms) and worth nothing, because the microtask queue drains *before* the browser renders. Cost is not the property being bought
- [x] **`Isolate.run` on native, measured**: round trip 0.05–0.09 ms, ~4 ns/int to bring a fact database home, 1.00× on a 75–91 ms job (0.16–0.22 ms of boundary). The rule the numbers give: export a job only when it is longer than the round trip; below that the chunked engine already there wins
- [x] **The Web Worker question, answered honestly and only as far as it was measured.** Not needed: chunking cleared the bar a Worker would have been introduced to clear. **Not verified** to work under dart2wasm — that was not measured, and the write-up says so rather than deferring it as folklore. The resumable shape is what keeps the option open
- [x] Gates: analyze clean, suite green, browser gate green (now carrying the yield test). No `lib/` code — a spike
- [x] **Carried into M-P1**: the `MessageChannel` yield needs a real home (`dart:js_interop`, behind a conditional import beside an `Isolate.run` native path) the first time an engine actually chunks. It is pinned here as a measurement, not shipped as an API — **landed in Phase 143** (`lib/domain/prover/event_loop_yield.dart`), when M-P2b's engine became the first consumer

## Phase 139 — the step budget is an amount of work, not a number of trials

Phase 134's last open decision. `dragStepBudget` shipped as the constant 128 (Phase 114); a degeneracy needs ~150 trials to cross (~90 to classify the starvation, ~20 for the arc, ~40 for the exit), so a coarse frame bails *just after* a successful detour and the static fallback relabels the root the detour carried. A constant is the wrong shape because a trial's cost scales with the construction. Decision recorded in PLAN §"The step budget is an amount of work, not a number of trials".

- [x] **Measured what a trial costs, and against what** — `benchmark/drag_budget_bench.dart` + `run_drag_budget.sh`, a *starving* frame (path ending on a tangency, so no arc can enclose the singular endpoint) across a 32× range of graph sizes. The per-trial figure is not the constant; **the per-object figure is**, and it is flat: 0.33 µs/object on the VM, 0.45 dart2js, 0.52 dart2wasm, 0.64 AOT. A path that merely *crosses* a degeneracy detours in ~66 trials at every size and measures nothing about the budget — that is why the harness ends its path on the singularity
- [x] **The old number was an over-read, and correcting it is half the phase.** "One trial is ~0.08 ms on the stress rig" (Phase 134, and the reason 512 was rejected as ~40 ms/frame) was a *frame* cost at 1.00 trials/frame — it charges every trial with the once-per-pass hoist and seed. The marginal trial is ~7× cheaper. The shape of the objection survives the correction; the arithmetic behind it did not
- [x] **The budget is derived per gesture** from the objects recomputed per trial: `dragStepBudgetWork ~/ perTrialObjects`, clamped. `TracingFlags.dragStepBudget` is now an `int?` **pin**, null by default. The *derivation* is captured once at session start (the graph is what it divides, and a drag cannot change the graph); the *pin* is read per frame, because a caller setting it mid-gesture means it now — which is what `drag_session_tracing_test`'s mid-drag `= 0` bail switch needs
- [x] **The work constant is the shipped constant restated** — 12288 = 128 × 96, the gate rig's downstream count — so that construction's budget does not move and the recalibration is visible as one. Its *time* cost is target-dependent by 2× and the slowest target ships to phones (~4.0 ms VM → ~7.8 ms AOT); calibrating on the gate rig is what keeps that today's worst case rather than a new one
- [x] **Loci are not per-trial work**, and the rule now lives in one place: `Construction._tracedPartition` splits the dependents into the core a trial recomputes and the loci a pass settles once (Phase 117b), and both the walk and `tracedWorkPerTrial` read it. They cannot drift — a kind that starts or stops being held back moves both together
- [x] **Floor 128** (the previous constant: no construction loses budget, graphs past the ~96-object crossover are untouched) and **ceiling 2048** (measured: a starving frame's cost flattens past ~500 trials while the counter runs, so the cap costs no capability)
- [x] **Coverage, and the payoff is that a test got to stop hand-tuning.** `drag_crossing_test`'s crossing at B was pinned at a hand-set 512 with a comment anticipating this phase; it now carries at the derived budget with nothing set, against a control at the old constant that still loses G to the driver's root. The frame straddling the carrier collapse at t = 0 is likewise now *crossed* rather than bailed on — pinned, with the bail-path test explicitly pinned back to 128 so that path keeps its coverage. Plus the derivation's own unit tests and the locus-exclusion pin
- [x] **Mutation-checked**: reverting the derivation to the constant fails exactly the four Phase 139 tests and nothing else; counting loci as per-trial work fails exactly its own test
- [x] Gates: suite **2756** green (2745 + 11), analyze clean, 32 goldens byte-identical, browser gate green, `flutter build web` compiles, drag-frame perf gate **PASS** unchanged (1% plain / 19% with a locus, checksums identical — a smooth frame spends one trial, so the budget never enters it)
- [ ] **Left open, named**: on a graph large enough for the floor to bind, a starving frame costs time linear in the graph *and* has too few trials to finish a detour — it pays and fails. Pre-existing, not introduced here; the fix is for a pass to decline a detour it cannot afford, and bail at once. Its own phase. Same shape as the AOT-with-a-locus overrun measured above

## Phase 137 — orientation is the representative's sign

The phase Phase 136c opened. Four line kinds (`TwoLineBisectorLine`, `PolarLine`, `RadicalAxisLine`, `TangentLine`) oriented their chart against their own representative via `_v1Direction()` chart reads, so a parent that lost its chart swapped the branch below it. The re-founding: the stored representative's sign *is* the orientation, the chart is a positive multiple of it, and every V1 direction convention becomes a projective sign formula. Chart behaviour stays identical wherever V1's convention spoke; representative behaviour becomes specified where it was arbitrary. See PLAN §"Orientation is the representative's sign".

- [x] **`ProjLine.toOrientedLineEq()`** — the sign-preserving projection: `line` is a positive multiple of the representative for real carriers (the `AngleBisectorLine` pattern, promoted; real parts, imaginary fallback for phase-scaled representatives). Null exactly where `toLineEq` is
- [x] **The point-representative contract: `w.re > 0` when real and finite** (`ProjPoint.wPositive`). Audited *empirically*: the gate (`point_representative_sign_test.dart`) sweeps both corpora at three layouts under all three absolutes and found eight offender kinds — the triangle centres, the transform kinds, `ProjectionPoint`, `HarmonicConjugatePoint` — plus the solver: **41% of real finite line∩conic candidates come back with `w < 0`** (measured over 5000 random pairs). Normalized at eleven kind store sites and inside the three `intersectionCandidates` builders, so candidates and stored points share the convention and bitwise membership comparisons keep holding. An exact `×(−1)`; suite moved by nothing
- [x] **All eleven line kinds project through the oriented representative** — `orientedAlong` deleted, every per-kind V1 direction recomputation with it, `RelativeLine.directionFrom` included. The four got their σ fixes *first*, so the swap was chart-preserving by construction. Pinned: the 136c measurement test inverted (eleven kinds, zero disagreements), and the join's p1→p2 promise pinned *through an `IntersectionPoint` parent* — the config the w-contract exists for, and the one an agreement gate cannot see (a chart derived from the rep agrees with it tautologically; the pin must be against parent positions)
- [x] **The four kinds re-founded**: `PolarLine` `×sign(tr Q · w_p)`; `RadicalAxisLine` `×sign(tr Q₁ · tr Q₂)`; `TangentLine` `−(A·t)` under the same factors, touch order by `det[adj(A)·ℓ∞, p, t]` divided by the rows' `w`s — exactly the chart cross product, so the *comparison* is V1's and not merely its sign; `TwoLineBisectorLine` `×sign(w_meet)` on the Euclidean route, `_anchored` deleted (branch semantics on the parents' representatives). **The real source of negative traces is `ThreePointCircle`**: its circumcircle determinant emits `tr Q < 0` for clockwise winding — same circle, opposite representative — which is what the 136c half-of-configurations measurement was. - [x] **The line∩conic ordering re-anchor in `intersectionCandidates` is deleted**, not re-pointed: `intersectLineConic` orders along the representative's direction, and that now *is* the V1 order. The Phase 110 flipped-representative stub test inverted — order and chart flip together, one source
- [x] **The defect regression, as it actually resolves**: the bisector below a chartless `PolarLine` names the same branch with and without the chart (the 136c demonstration inverted); the oriented polar representative is continuous through the pole-at-centre chart event (the state grid snapping lands on); and a chartless carrier now *specifies* orientation and tangent order — an ellipse's tangents from an outside pole order left-first where solver order previously stood

## Phase 132c — a locus driven by a point on a conic

Phase 132 made a general conic a curve a point can be glued to and left the locus behind: `_SweepDomain.of` asked a `GeoCircle` host for its `CircleEq` and gave up when there was none, so a locus driven by such a point had **no samples at all** — silently absent, which is the harder kind to notice.

- [x] **The domain is the pencil circle the point is already glued on**: `φ = π·x`, cyclic with period 1, one bijection from `[0, π)` onto the whole curve. `pointAt` *is* `pointAtComplex` at a real angle, so the real and complex evaluations are one expression and a detour rejoins the real axis bitwise with nothing kept in step by hand — the property the line and circle arms buy with two parallel formulas each
- [x] **`ConicShape.chartLiftAt` — the pencil value a tracing consumer can take.** `pointAtComplex` is polynomial and homogeneous, so it answers at whatever scale the algebra leaves: **`w = −0.079` at `φ = 0.3`** on `x²/16 + y²/4 = 1`, and *negative*. `PointOnObject.tracedPosition`'s contract is `w` exactly one or exactly zero, because `position` reads x and y straight back without dividing (so a sweep along a diverging arm keeps full precision). Hand over the raw value and every chain member reading the driver's chart position gets it rescaled and, half the time, reflected
- [x] **The drag path had the same hole, and its two sibling arms did not.** `Construction._chartEvaluator`'s conic arm returned `pointAtComplex` directly; the line and circle arms both build `w = Complex.one` by hand. - [x] **The ellipse is the class that is swept**, on the gate `extentAlong` already states: an ellipse is the only conic whose curve is bounded. No object reaches that state today, and the guard says so rather than trusting that it stays true
- [x] **Making the circle arm a `circle?` pattern made every arm below it reachable for the first time**, `default:`'s `StateError` included. The settlement is `branchIndex`'s, not the sketch the phase was opened with: recompute stays pure and canonical; the drag session carries identity across each switch; the command adopts the net re-expressions. See PLAN §Parameterization.

- [x] **`ConicShape.frameSeeds`** — the base-point candidates the canonical constructor chooses among, recomputed by the same operations so the canonical choice is **bitwise a member** (pinned over all three curve classes). - [x] **`ConicShape.carryParameterFrom`** — hands the angle back *identically* where the canonical frame continues the previous one (the common case pays nothing and drifts nowhere — pinned on the clean rotating near-circle, 200 steps, all bitwise no-ops); at a switch, replays the previous frame on the new matrix and reads the angle back canonically, so the named point does not move (pinned: the switch step stays at the figure's own motion scale). - [x] **`_GlueTracker`** in the translate drag session — the `_BranchSnapshot` shape: per preview frame, compares every affected circle-kind host's parameterization frame with the previous frame's and re-expresses each glued parameter across a switch, the polar-angle ↔ pencil-angle boundary included (a host crossing the `CircleEq` projection tolerance flips the parameter's *meaning*; only the position carries). Rollback restores the start parameters bitwise; both single-point and rigid-translation paths are covered
- [x] **`GlueChange` on the commands** — `MoveFreePointCommand.glueChanges` and `TranslateObjectsCommand.glueChanges`, applied before the moves like branch adoptions so one topological pass settles, replayed on apply and undo. A switch-free gesture commits none

## Phase 127 — `RotatedPoint`, and the deferral re-examined

The last piece of Phase 125's per-kind debt that was a **gap** rather than a refusal. The deferral said a CK rotation about a general centre needs an orthonormal frame in the pencil through it, and that the sign of the dual form varies across that pencil so the angle is not uniformly circular. **The second half is true; the first is not** — and the half that is true is about the *centre*, not the pencil. See PLAN §"A rotation is the exponential of one generator".

- [x] **No frame, because the isometries are a Lie group.** The maps preserving the absolute have Lie algebra `{Ω⁻¹K : K antisymmetric}`, every antisymmetric 3×3 is a cross-product `[C]ₓ` with kernel `C`, so the group fixing `C` is `exp(t·Ω*[C]ₓ)` with no basis chosen anywhere. The generator satisfies `N³ = −λ²N`, which closes the exponential into Rodrigues' formula — two matrix products, no series. `ProjTransform.ckRotation`
- [x] **One formula for all three geometries**: expanded under the Euclidean dual `diag(1,1,0)` it reproduces the shipped `ProjTransform.rotation` **entry for entry**, `λ = 1` included, over a spread of centres and angles. Same relationship `harmonicHomology` has to `reflection`. The Euclidean route is kept anyway, exact and cheaper, per the Phase 122/124 rule
- [x] **The sign of `λ²` is the classical trichotomy, and it is where the deferral was right.** `λ²` is the absolute's form at the centre up to sign and scale: positive → interior, and the pencil through an interior point misses the dual conic entirely so its angle measure is elliptic and the rotation is as circular as a Euclidean one; zero → on the absolute, a parabolic horolation with no angle; negative → outside, a boost along the centre's polar whose parameter is a **rapidity**. The last two refuse with the zero map, because `cos`/`sin` there would answer with a *different* isometry rather than an approximate one
- [x] **Two conventions pinned rather than inherited.** The sign of `λ` is free and the stored hyperbolic dual is the adjugate (`−Ω⁻¹`), so a generator taken at face value turns clockwise in one geometry and counter-clockwise in another — handedness is anchored so positive angles are counter-clockwise in the chart in all three. And the centre is **dephased first**: `λ²` scales as `k²`, so an `i`-scaled representative of an ordinary interior centre would fail the realness test and be refused as a boost
- [x] `ProjPoint.dephased` promoted out of `ck_measure.dart`'s private canonicalization, with the Phase 125 exactness note that made it a *phase* division rather than a component division. `_canonical` now delegates, same arithmetic

## Phase 125 — M-CK2: the tier-2/3 substitutions

The bulk of the milestone: 32 kinds. Taken in the audit's order — the verbatim pole/polar generalizations first, then the genuine re-foundings, then the refusals. **Zero Euclidean behaviour change** throughout.

- [x] `euclidean.dart` → **`metric.dart`**, every function taking an `Absolute`. It was never only Euclidean; it was the Euclidean case of a family
- [x] **Midpoint and angle bisector are the same construction, dually** (PLAN §"Two constructions, one algebra"). A midpoint is the pair harmonic to `{P,Q}` and to the absolute's two points on `PQ`; parameterizing `X(t) = P + tQ`, harmonic to `{0,∞}` forces `M₋ = −M₊`, and harmonic to the absolute's roots forces `t² = ⟨P,P⟩/⟨Q,Q⟩` — so `M± = √⟨Q,Q⟩·P ± √⟨P,P⟩·Q`. Under Euclidean `⟨P,P⟩ = w²` and that reads `w_Q·P ± w_P·Q`: **the affine midpoint, plus the point at infinity in direction `P−Q`** — the external midpoint, whose sitting at infinity is why Euclidean seems to have one. The same algebra in the dual gives `B± = √⟨m,m⟩*·ℓ ± √⟨ℓ,ℓ⟩*·m`, which under `diag(1,1,0)` is exactly the √-unitization `twoLineBisectorOf` already had
- [x] Perpendicularity generalizes verbatim — `perpendicularThrough(P,ℓ) = P ∨ absolute.poleOf(ℓ)`, the audit's structural claim, now a test
- [x] `parallelThrough` **refused** under a proper absolute (zero triple), not approximated
- [x] Two cross-cutting fixes the tests found: **conjugacy is perpendicularity** in every CK geometry, so a vanishing pairing between two *non-isotropic* lines is a right angle whatever the self-pairings' signs (a line and its perpendicular can sit on opposite sides of the absolute, making the product under the root negative); and **every measure removes a global phase first**, because the CK constructions take a square root of a form that is negative inside the absolute and hand back real elements scaled by `i`. The normalization divides by the pivot's unit *phase*, not the pivot — it must be exact, since the perpendicularity test is an exact zero and rounding it to 2.7e-17 lost every right angle it touched
- [x] The eleven `metric.dart` consumer kinds wired, with the absolute threaded through the two template methods (`TriangleCenterPoint.computeCenter`, `RelativeLine.carrierFrom`) rather than each override reaching for it
- [x] **Transforms**: `ProjTransform.harmonicHomology` added, and it reproduces the shipped Euclidean reflection matrix **entry for entry** — the audit's claim that reflection *is* the homology about `(axis, its pole)`, checked rather than asserted; point reflection is the homology about `(centre, its polar)`, ℓ∞ under Euclidean, which is why it reads as a homothety of −1
- [x] **Circles** in `ck_circles.dart`, and they split the way distance splits (PLAN §"A circle follows its distance measure"). `d(C,X) = r` squares to `⟨C,X⟩² = k⟨C,C⟩⟨X,X⟩`, i.e. `K = ⟨R,R⟩(ΩC)(ΩC)ᵀ − ⟨C,R⟩²Ω` — the pencil through the absolute and the doubled polar of the centre, hence **bitangent**. Under Euclidean that whole pencil collapses to multiples of ℓ∞, so `circles.dart` is a *companion*, not a special case. A centre on the absolute is a **horocycle**, not a degeneracy. `Arc`/`Sector` refused: the carrier generalizes, the angular extent is a chart parameterization
- [x] The five re-foundings, and **three of them turned out to generalize** because their definitions are constructions rather than formulas: the centroid is the medians' common point (CK midpoints), the incentre the internal bisectors' (CK bisector), the inscribed circle centred there through the foot of a perpendicular. `FixedRadiusCircle` gets `ckCircleWithRadius`. Refused with reasons at the site: homothety and translation (a similarity that is not an isometry does not exist in CK — Wallis), rotation (needs an orthonormal frame in the pencil, whose form changes sign across it), Apollonius and bifocal conics, the radical axis, the focal conic, the circle centre (a generalized eigenproblem for the pencil `{K, Ω}`), segment-ratio points
- [x] `IntersectionPoint`'s circular-point filter made absolute-aware, and threaded **all at once** because `branchIndex` addresses the *filtered* order — a caller left on the default lands its points in a different address space, the Phase 120c failure from a new direction. One caller knowingly stays on the default and says so: the tool layer has no construction to read a kernel from, which is correct only while the codec refuses non-Euclidean documents. **Phase 126 must carry the kernel into the tools before lifting that refusal**
- [x] **The `recompute` default is kept, and that reverses Phase 124's schedule on purpose.** The Phase 121 precedent says a migration default inverts into a trap once the migration ends — but the trap it described was a kind *silently inheriting* a wrong value, and that cannot happen here: the parameter is supplied by `Construction` at every production call site, so the default only ever applies in tests that mean Euclidean. The risk that remains is a new kind whose `recompute` ignores the parameter, and a signature cannot catch that — only behaviour can. `ck_kind_coverage_test` does: over the corpus at three layouts, every kind must change its value or withdraw it. That is a strictly stronger gate than the one removing the default would buy, and it costs ~140 test call sites less churn
- [x] ~~**A coverage gate, not a proof.**~~ — the proof it was missing is `ck_isometry_invariance_test` (Phase 131), and the coverage gate's own blind spot is what it found: a kind with *one* of two ingredients substituted still moves, so `ck_kind_coverage_test` passed `Orthocenter` while one of its altitudes was Euclidean. Equivariance is not a substitute for per-kind correctness — a kind computing the wrong *equivariant* thing would pass — but it rules out the family of defects per-kind tests were being written one at a time to catch

## Phase 124 — M-CK1: measurement, and the half of it that is not a cross-ratio

PLAN §M-CK said the tier-4 kinds are "re-founded on cross-ratio, with Euclidean as the degenerate case that reproduces today's numbers". **Measured first: that is true of angle and false of distance**, which is the classical Cayley–Klein classification arriving as a code constraint — Euclidean has *elliptic angle measure* and *parabolic distance measure*.

- [x] **Angle unifies, at the bilinear-form level rather than through logs.** `cos θ = ⟨ℓ,m⟩*/√(⟨ℓ,ℓ⟩*·⟨m,m⟩*)` against the *dual* absolute is Laguerre's cross-ratio formula with the logs cleared, and under `diag(1,1,0)` it is `(a₁a₂+b₁b₂)/(|n₁||n₂|)` — the textbook Euclidean formula, verbatim. Measured: agrees with the chart route to **7.4e-13** over 20k random line pairs
- [x] **Distance does not unify, and cannot.** A line meets the Euclidean absolute (the *doubled* ℓ∞) in one point twice, and a cross-ratio with a repeated point is identically 1, so the log is identically 0 for every pair of points. Euclidean distance is not a cross-ratio at any constant — recovering it needs the constant to diverge as the absolute degenerates. So distance **dispatches on the measure** where angle substitutes: parabolic (Euclidean, the chart route it already uses), hyperbolic (`cosh d = |⟨P,Q⟩|/√(⟨P,P⟩⟨Q,Q⟩)`), elliptic (the same with `cos`). Verified against `artanh(r)` and against the cross-ratio route to the last digit
- [x] Thread the absolute into `recompute`, per Phase 123's decision — **defaulted to Euclidean while the migration runs**, which is the pattern Phases 106–121 already used for the projective accessors and then removed. Scheduled for removal at the end of Phase 125, when all 38 kinds take it; `Construction` passes `kernel.absolute` from the start, so the default is scaffolding at the declarations and never a live fallback
- [x] `Absolute` gains the bilinear pairings (`pairPoints`, `pairLines`) the quadratic forms of Phase 123 polarize to; `lib/domain/projective/ck_measure.dart` holds the two measures and names the three measure kinds
- [x] `VertexAngle` and `LineAngle`: the CK formula becomes the *definition*, with the exact Euclidean route retained as its specialization — the Phase 122 circle-fast-path rule, for the same reason (it is exact, cheaper, and keeps `expect(angle, 90)` reading exactly 90). Agreement proven by test rather than by routing. The marker's vertex and start direction stay chart quantities, like a measurement's anchor
- [x] `DistanceMeasurement` on the three measures. `LengthMeasurement` and `AreaMeasurement` are **integrals**, not substitutions (hyperbolic circumference is `2π·sinh r`, and a hyperbolic triangle's area is its angular defect) — deliberately **not** implemented here, and undefined rather than wrong under a proper absolute. `SlopeMeasurement` is Euclidean by definition and goes undefined with the others
- [x] Gates: **zero Euclidean behaviour change** — suite **2438** green, analyze clean, **32 goldens byte-identical**, perf gate PASS at 1% / 7% of budget with unchanged checksums. Every non-Euclidean path is reachable only from tests this phase, since the codec still refuses the two other metrics. Also added: `GeoAngle.measure` beside `angle`, because a marker is not a measure — the arc is still drawn between the same two chords while the number is the CK angle
